三个核心操作

sync-profile init

种子包 → 新环境 / 新项目
  • 读取种子包 profile/ → 写入全局 CLAUDE.md
  • 读取 config/ → 合并到全局 settings.json
  • 按项目类型选模板 → 生成项目 CLAUDE.md
  • 生成项目 docs/ 骨架 + .claude/settings.local.json
  • 生成 docs/LESSONS.md（来自 knowledge/）
🤖 init 后新项目的 AI 已经认识你了

sync-profile pull

项目经验 → 追加到种子包
  • 读取项目的 docs/LESSONS.md
  • AI 提取新增条目，判断归入哪个文件
  • 确认的自动归类 + 展示操作清单
  • 不确定的停下来问你
  • 你扫一眼清单，确认后追加
👤 看一眼操作清单，有问题及时纠正

sync-profile refresh

种子包更新 → 已有项目同步更新
  • 对比 seed.yaml 版本号
  • 种子包有新增 → 覆盖项目模板部分
  • 保留项目自定义内容（LESSONS.md 你填的坑不动）
  • 脚手架改了（如 ARCHITECTURE.md → REFERENCE.md）→ 项目跟着变
🤖 只在模板层覆盖，不动你写的内容

🔧 关键设计：脚手架切换（解决 "以后换文档方式"）

scaffolds/rust-tauri/
├── CLAUDE.md.hbs
├── LESSONS.md.hbs
├── REFERENCE.md.hbs ← 换成这个
├── design-system.md.hbs
└── settings.local.json.hbs
你改种子包里的脚手架模板 → 在已有项目跑 sync-profile refresh → 旧项目检测到模板变了 → 删除 ARCHITECTURE.md（但你写的注释不会丢，先询问你）→ 生成新的 REFERENCE.md 骨架。 新项目跑 init 直接就是新模板。
